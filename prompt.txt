# FieldLine — PASS 19: HUMAN REVIEW WORKFLOW

Implement **Pass 19 — Human Review Workflow** in the existing FieldLine repository.

Approved base:

```text id="base19"
c4011ecdb2671a2c9f234168a6c5fc189dfc3185
```

Do NOT implement Pass 20+.

---

# 1. Objective

Handle uncertain AI/activity matches safely.

Required policy:

```text
HIGH confidence
    ↓
automatic confirmation

MEDIUM confidence
    ↓
suggested match
    ↓
human confirms/rejects

LOW confidence
    ↓
unresolved
    ↓
human chooses activity
```

Core invariant:

```text
No ambiguous AI match silently becomes canonical project truth.
```

The human review workflow must be project-scoped, auditable, deterministic, and compatible with the existing ActivityMatchingService and ProgressService.

# 6. Required confidence policy

Conceptually:

```text id="policy19"
HIGH:
  score >= HIGH_THRESHOLD
  AND top candidate is sufficiently separated from runner-up

MEDIUM:
  score >= MEDIUM_THRESHOLD
  BUT does not satisfy HIGH/auto-confirm conditions

LOW:
  score < MEDIUM_THRESHOLD
```

The exact thresholds should be centralized constants.

Additional hard rules:

### Exact-ID matches

An exact activity ID is the strongest existing match method.

It may qualify for auto-confirmation when it uniquely identifies one project activity.

Still preserve project isolation.

### Ambiguous high scores

Example:

```text
A = 0.91
B = 0.90
```

must NOT automatically confirm A.

Treat it as ambiguous and route it to human review.

### Single strong candidate

Example:

```text
A = 0.91
next = none
```

may auto-confirm if the configured high-confidence policy permits it.

# 8. High-confidence automatic confirmation

When the review policy determines:

```text id="high19"
tier = high
AND
autoConfirm = true
```

the match must be persisted as:

```text
status = confirmed
reviewedBy = 'system'
reviewedAt = current timestamp
```

or an equivalent explicit system-review representation.

Do NOT pretend this was a human review.

Clearly distinguish:

```text
system confirmed
```

from:

```text
human confirmed
```

If the current domain model needs a deterministic representation, inspect existing audit/review conventions and choose the smallest compatible change.

The project event should make the source explicit.

# 10. Low-confidence behavior

For:

```text id="low19"
tier = low
```

do NOT silently convert the best candidate into project truth.

A low-confidence candidate must be treated as unresolved.

Choose the minimal compatible architecture.

Preferred approach:

```text id="lowmodel19"

+
persist confidenceTier = low
+
mark reviewState = unresolved
```

Do not add a destructive or ambiguous interpretation of `suggested`.

The UI must clearly indicate:

```text id="lowdisplay19"

Low confidence

```

The user must be able to choose the correct activity from the project activities.

# 14. Confirm semantics

Confirm should:

```text id="confirm19"
verify match
verify project
verify status permits confirmation
update:
  status = confirmed
  reviewedBy = supplied reviewer identity
  reviewedAt = now
emit match_confirmed event
```

Do not let a rejected match be silently resurrected without an explicit rule.

If the current application does not have authenticated user identity, use the existing reviewer field convention and document the limitation.

Do not invent a full authentication system in Pass 19.

---

# 15. Reject semantics

Reject should:

```text id="reject19"

verify project
update:
  status = rejected
  reviewedBy
  reviewedAt
emit match_rejected event if the event model is extended
```

Do not delete the match record.

Historical review decisions must remain auditable.

Do not automatically replace it with another candidate.

# 16. Resolve low-confidence match

For unresolved low-confidence cases:

```text id="resolve19"
human selects Activity B
```

The application must:

1. verify Activity B belongs to the same project
2. verify the match belongs to the same project
3. update the existing match to the appropriate resolved state
4. set:

```text
reviewedBy
reviewedAt
matchMethod = 'manual'
```

5. preserve the original AI confidence/rationale
6. emit a review event

Do not overwrite the historical confidence score.

The fact that a human resolved it must remain distinguishable from the original AI score.

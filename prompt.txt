# MISSION BRIEF: GEMINI LIVE SPEECH-TO-SPEECH INTERACTION CAPABILITY FOR FIELDLINE

## OVERVIEW & OBJECTIVE
FieldLine is an intelligent infrastructure project management platform. Non-technical workers on construction sites need a seamless, hands-free voice interface to:
1. **Report Progress**: Workers verbally describe task completions (e.g., "We finished casting the concrete slab on Pier 12"). Gemini Live acknowledges receipt conversationally, sends the isolated statement to Groq (`openai/gpt-oss-20b`) for deterministic structured extraction and schedule linking, and—once the database update commits—verbally announces confirmation: *"Update verified: Pier 12 excavation is saved at 100%"*.
2. **Ask Context-Aware Project Questions**: Workers confused about the next best step can ask questions (e.g., "What are we scheduled to work on next at Block B?"). Gemini Live answers conversationally using injected project context and real-time SQLite database queries (tools).
3. **Handle Accents & Site Noise ("Pardon Me" Protocol)**: When speech is muffled, noisy, or accented, Gemini Live MUST ask for polite clarification instead of guessing or hallucinating.
4. **20-Key Gemini Rotation & Seamless Session Handover**: Utilizes 20 Gemini API keys (`GEMINI_API_KEY_01` to `GEMINI_API_KEY_20`) created from distinct Google AI Studio accounts in a sticky round-robin order. When a session approaches the 65,000 TPM limit or encounters a rate limit, the system smoothly switches to the next key without dropping the audio stream or losing conversational context.
5. **UI Integration**: The Live Voice button is embedded directly inside the existing floating AI assistant panel (`FloatingAIAssistant.tsx`).

---

## CRITICAL ARCHITECTURAL CONSTRAINTS & VERIFIED SPECS
- **Model**: Strictly use Gemini 3 Flash Live (`gemini-3.1-flash-live-preview` via `GEMINI_LIVE_MODEL` in `.env`).
- **Connection Architecture**: Browser connects to a **FieldLine Backend WebSocket Gateway** (`ws://localhost:3001/ws/live-session`). The backend proxies the connection to Google's Multimodal Live API (`wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1alpha.GenerativeService.BidiGenerateContent?key=...`). **DO NOT** connect the browser directly to Google (protects API keys and enables invisible key handovers).
- **Session Handover Strategy**: Google's native `session_resumption.handle` is cryptographically locked to the initiating Google Cloud project and yields `PERMISSION_DENIED` across different keys. Therefore, the backend gateway maintains an **application-level rolling conversation buffer**. When rotating keys, the gateway boots a new upstream WebSocket on Key $N+1$, hydrates it with the recent conversation summary + active context, transfers the browser's audio stream, and terminates Key $N$.
- **Audio Specifications**:
  - Client Input: 16-bit Linear PCM, Little-Endian, 16,000 Hz (16 kHz), mono, Base64-encoded (`audio/pcm;rate=16000`).
  - Server Output: 16-bit Linear PCM, Little-Endian, 24,000 Hz (24 kHz), mono, Base64-encoded (`audio/pcm;rate=24000`).
- **Transcription**: Native `inputAudioTranscription: {}` and `outputAudioTranscription: {}` must be enabled in the session `setup` message.
- **Two-Stage Verbal Verification**:
  - Stage 1 (Immediate Voice Acknowledgment): Gemini Live acknowledges receipt verbally (e.g. *"Understood, recording that Pier 12 excavation is finished. Logging that now."*).
  - Stage 2 (Post-Groq & DB Confirmation): When Groq + SQLite commit the record, the backend prompts Gemini Live to verbally confirm: *"Update verified: [Activity Name] is saved at [Progress]%."*

~~### Pass 2: Backend Live WebSocket Gateway & Upstream Gemini Live Engine~~
**Objective**: Create the backend WebSocket server and upstream Gemini Live WebSocket bridge with application-level session handover.

**Requirements**:
1. **Dependencies & Server Setup**:
   - Install `ws` and `@types/ws` if not present (`npm install ws`, `npm install --save-dev @types/ws`).
   - In `backend/src/index.ts` and `backend/src/app.ts`, integrate the `ws` WebSocketServer attached to the main HTTP server on the path `/ws/live-session`.
2. **Implement `backend/src/ai/live/upstream-gemini-socket.ts`**:
   - Manages a persistent WebSocket connection to:
     `wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1alpha.GenerativeService.BidiGenerateContent?key=${apiKey}`
   - Sends the initial `setup` frame:
     - `model`: `models/${env.GEMINI_LIVE_MODEL}`
     - `generationConfig.responseModalities`: `["AUDIO"]`
     - `generationConfig.inputAudioTranscription`: `{}`
     - `generationConfig.outputAudioTranscription`: `{}`
     - `systemInstruction`: Site worker persona + "Pardon Me" accent/clarification rules + Project Context summary.
     - `tools`: Function declarations for `get_next_recommended_activities`, `lookup_activity_status`, and `record_field_progress`.
   - Parses upstream server messages:
     - Extracts `audio/pcm;rate=24000` from `serverContent.modelTurn.parts` and emits to client.
     - Extracts `serverContent.inputTranscription` (worker speech) and `serverContent.outputTranscription` (Gemini speech).
     - Extracts `toolCall` and `usageMetadata`.
     - Handles `turnComplete` and `interrupted` events.
3. **Implement `backend/src/ai/live/gemini-live-gateway.ts`**:
   - Manages client browser WebSocket connections: accepts `projectId` as query parameter.
   - Allocates an active key from `GeminiKeyRouter`.
   - Bridges client audio chunks (16kHz PCM Base64) to the upstream Gemini socket via `realtimeInput.mediaChunks`.
   - Maintains an in-memory **Rolling Conversation Buffer**:
     - Keeps the last $N$ turns of user input and model output text.
     - Keeps active project summary and progress reports in flight.
   - **Seamless Handover Engine**:
     - When Key $N$ reaches the token limit or triggers 429:
       1. Requests Key $N+1$ from `GeminiKeyRouter`.
       2. Opens a new upstream Gemini connection with Key $N+1$.
       3. Injects a context summary of the ongoing conversation into the new setup / `clientContent`.
       4. Redirects the incoming browser audio stream to the new connection.
       5. Gracefully closes the old connection. The browser connection is NEVER interrupted.
4. **Tests**:
   - Write integration tests in `backend/tests/gemini_live_gateway.test.ts`:
     - Gateway client connection and query parameter validation.
     - Protocol message routing (audio chunks, transcriptions, interruptions).
     - Key handover simulation on mock rate limit / token limit event.

~~### Pass 3: Real-Time Context Grounding, Live Tool Execution & Groq Verbal Confirmation Loop~~
**Objective**: Connect Gemini Live's tools to FieldLine's SQLite database and wire the two-stage progress update loop to Groq (`openai/gpt-oss-20b`) with verbal confirmation.

**Requirements**:
1. **Implement `backend/src/ai/live/live-tool-handlers.ts`**:
   - `get_next_recommended_activities(projectId, location)`:
     - Queries `activityRepository` for activities with status `not_started` or `in_progress` in the project (optionally filtered by location).
     - Returns top 5 prioritized tasks with code, name, location, and planned dates.
   - `lookup_activity_status(projectId, query)`:
     - Uses `DeterministicActivityResolver` to resolve the activity by code or name.
     - Returns verified planned/actual progress, variance state, and delays.
   - `record_field_progress(projectId, rawStatement)`:
     - Immediately returns a tool execution result to Gemini Live confirming intake:
       `{ status: "queued", message: "Progress statement captured. Verifying and committing to project schedule." }`
     - Asynchronously passes `rawStatement` to `FieldProgressExtractionService` (`extractFromReport` using Groq `openai/gpt-oss-20b`).
     - Calls `progressUpdateService.createManualUpdate` with `sourceType = 'voice'`.
     - Normalizes and links the extracted item via `progressService.normalizeAndRecordProgress`.
     - **Verbal Confirmation Trigger**:
       - Once the database transaction commits, the gateway dispatches a high-priority system turn or `clientContent` to Gemini Live:
         *"System Event: Progress update committed successfully. Activity: [name] ([code]), Progress: [percentage]%. Verbally inform the worker: 'Update verified: [name] is saved at [percentage]%.'"*
       - Gemini Live generates audio speaking this confirmation directly to the worker.
2. **Context Snapshot Builder for `systemInstruction`**:
   - In `backend/src/ai/live/live-context-builder.ts`:
     - Builds concise static snapshot for the project: Project code, active milestones, today's date, and high-level progress.
     - Formats strict "Pardon Me" prompt instructions:
       *"If any activity code, location, or quantity is phonetically unclear, muffled, or ambiguous, ask back for pardon: 'Pardon me, did you mean Section B or D?' Never guess or hallucinate unconfirmed progress."*
3. **Tests**:
   - Write tests in `backend/tests/gemini_live_tools.test.ts`:

     - Database queries returning accurate SQLite records for `get_next_recommended_activities` and `lookup_activity_status`.
     - End-to-end simulation of `record_field_progress` -> Groq extraction -> SQLite write -> verbal confirmation generation.

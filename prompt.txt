# 1. Objective

Move expensive document ingestion out of the HTTP request path.

Current Pass 14 behavior is synchronous:

```text
POST /evidence/:evidenceId/process
        ↓
DocumentIngestionService.processEvidence(...)
        ↓
document extraction
        ↓
AI extraction
        ↓
ProgressUpdate
        ↓
Evidence linkage
        ↓
ActivityMatchingService
        ↓
HTTP response
```

Pass 15 must change this to:

```text
POST /evidence/:evidenceId/process
        ↓
create SQLite processing job
        ↓
HTTP 202 Accepted
        ↓
same Node process worker
        ↓
claim job
        ↓
DocumentIngestionService.processEvidence(...)
        ↓
completed / failed
```

No separate deployment service is required.

No separate worker process is required.

No Redis or external queue is allowed.

# 13. Job claiming

Claiming a queued job must be safe against accidental double execution.

Even though Pass 15 uses one worker, implement claim semantics in SQLite so the intended state transition is explicit.

A job should only be claimed if:

```text
status = 'queued'
```

and claiming should atomically set:

```text
status = 'processing'
started_at = now
locked_at = now
attempt_count = attempt_count + 1
updated_at = now
```

The repository should return the claimed job or null.

Do not hold a SQLite transaction open while performing:

* PDF parsing
* OCR
* AI calls
* document extraction

The database transaction is only for job-state transition.

---

# 14. Worker execution

For a claimed job:

1. validate payload
2. verify evidence still exists
3. verify evidence belongs to job.projectId
4. call:

```ts
documentIngestionService.processEvidence(
  job.projectId,
  payload.evidenceId
)
```

5. on success:

   * serialize a bounded result
   * mark job completed
6. on ordinary processing failure:

   * mark job failed
   * store sanitized error message
7. continue worker loop

A failed job must NOT crash the Node process.

The worker must continue processing later jobs.

---

```json
}
```

The complete underlying records remain available from the existing Evidence, ProgressUpdate and ActivityMatch APIs.

# 17. Stale job recovery

On worker startup, recover abandoned jobs.

Conceptually:

```text
processing job
+
locked_at is older than configured lease threshold
        ↓
requeue
        ↓
queued
```

Add:

```text
requeueStaleProcessingJobs()
```

to the job repository.

The threshold must be configurable.

Do not use an extremely small timeout because OCR/PDF/AI processing can legitimately be slow.

Do not reset every processing job immediately unless the implementation can prove it belongs to a dead worker.

A practical local-worker lease is sufficient for this pass.

# 18. Worker lifecycle

Current `backend/src/index.ts` does:

```text

createApp()
app.listen()
```

and has graceful SIGINT/SIGTERM handling.

Extend it to:

```text
initDatabase()

start worker
create app
start HTTP server
```

On shutdown:

```text
stop accepting new work
stop worker polling
allow current job state to settle according to the chosen shutdown policy
close server
close database
```

Do NOT terminate the process while a worker is actively executing in a way that would leave state incorrectly marked as completed.

A clean approach is:

```text
stop scheduling new jobs
wait for current worker iteration
close server
close DB
```

The implementation does not need elaborate shutdown orchestration.

# 21. Project isolation

All job operations must be project-scoped.

Examples:

```text
Project A cannot retrieve Project B's job.

Project A cannot enqueue a job for Project B evidence.

Project B cannot claim a Project A job.

Cross-project job status access must return 404.
```

The database should enforce:

```text
processing_jobs.project_id → projects.id
```

The service must also verify the Evidence project association before processing.

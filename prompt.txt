The current FieldLine `main` contains the approved Pass 20 dashboard.

1. Move dashboard aggregate actual/planned progress calculation into the canonical Progress Snapshot layer.

# 10. Improvement B — remove dashboard recent-update N+1 queries

## Current issue

The dashboard currently:

1. fetches progress updates
2. loops over updates
3. for EACH update fetches:

   * matches
   * ActivityProgress observations
   * evidence

This creates a query pattern approximately:

```text
1 query for updates
+
N queries for matches
+
N queries for observations
+
N queries for evidence
```

For the default 10 updates, that is roughly:

```text
31 queries
```

for the recent-update section alone.

This is unnecessary even in local SQLite.

---

# 11. Required batch repository APIs

Add project-scoped batch methods to existing repositories.

Do NOT create a new data-access layer.

Recommended methods:

```ts id="batchapis20"
ActivityMatchRepository.listByProgressUpdateIds(
  progressUpdateIds: string[],
  projectId: string
): ActivityMatch[]

ActivityProgressRepository.listByProgressUpdateIds(
  progressUpdateIds: string[],
  projectId: string
): ActivityProgress[]

EvidenceRepository.listByProgressUpdateIds(
  progressUpdateIds: string[],
  projectId: string
): Evidence[]
```

Use names consistent with the repository conventions if slightly different.

The critical requirement is:

```text
one bounded batch query per repository
```

rather than one query per progress update.

---

# 12. SQL requirements for batch methods

Use:

```text id="sql20"
WHERE project_id = ?
AND progress_update_id IN (...)
```

or the equivalent safe SQL.

Do NOT construct SQL by concatenating user-controlled values.

Generate placeholders programmatically.

Handle:

```text id="emptybatch20"
progressUpdateIds.length === 0
```

by returning:

```text
[]
```

without running a useless SQL query.

---

# 13. Project isolation

Every batch query MUST remain project scoped.

Never use:

```sql
WHERE progress_update_id IN (...)
```

without:

```text
project_id = ?
```

This is especially important because IDs are not sufficient authorization boundaries.

Add tests that verify:

```text id="batchisolation20"
Project A batch request
→ cannot return Project B matches

Project A batch request
→ cannot return Project B observations

Project A batch request
→ cannot return Project B evidence
```

---

# 14. Deterministic ordering

Batch repository methods must return deterministic order.

For example:

```text id="matchorder20"
ORDER BY progress_update_id, confidence_score DESC, id ASC
```

and appropriate equivalents for:

```text
ActivityProgress
Evidence
```

The dashboard can then group them in memory.

Do not depend on SQLite's implicit row order.

The per-update loop must perform only in-memory lookups.

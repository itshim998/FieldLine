# CURRENT ISSUE

The Worker/Admin "Operational Field Assistant" currently fails to resolve a valid natural-language activity query.

Exact user query:

"Pump foundation piles completed to 65% at Area B crude pump bay."

Current UI result:

"No activity matching "Pump foundation piles" was found in project "Refinery Expansion — Unit 4"."

This is incorrect.

The query is explicitly intended to resolve to:

ACT-B02 — Crude Pump Foundation Piling Works
Location: Area B

The repository's own README describes this exact phrasing as a supported heterogeneous-language scenario:

"Pump foundation piles completed to 65%"

and states that heterogeneous field descriptions should map to canonical schedule activities.

Therefore this is a real regression/functional gap in the text-based project assistant and must be fixed.

===================================================

1. CONFIRMED ROOT CAUSE
   ===================================================

Relevant files:

backend/src/services/assistant/assistant-intent.service.ts
backend/src/services/assistant/assistant.service.ts
backend/src/services/assistant/activity-resolver.ts
backend/src/services/matching/text-similarity.ts
backend/tests/assistant_service.test.ts
backend/tests/assistant_security.test.ts
README.md

Current architecture:

1. AssistantIntentService interprets the user question into:

   * intent
   * activityQuery
   * explicitDate

2. AssistantService passes activityQuery to:
   DeterministicActivityResolver.resolve(projectId, activityQuery)

3. DeterministicActivityResolver currently performs:

   * exact externalId
   * exact activity name
   * exact name + location
   * unique textual substring/token matching

The current final textual fallback requires all query words to be contained in:

external ID + activity name + location

The problematic example becomes approximately:

query:
"Pump foundation piles"

canonical activity:
"Crude Pump Foundation Piling Works"

Current word comparison:

pump       -> matches
foundation -> matches
piles      -> DOES NOT match "piling"

Therefore the resolver returns:
status = not_found

AssistantService then correctly displays its "No activity matching..." message.

DO NOT treat this as an AI-provider failure.

DO NOT fix this by changing the assistant's fallback answer.

Fix the activity resolution itself.
